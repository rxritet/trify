# Проверка прототипа правил Firestore

## Модель данных

- Путь: `users/{Firebase Auth UID}/planner/state`.
- `ownerId`: неизменяемая строка, совпадающая с UID в пути.
- `planner`: карта с массивами `trips` (до 100) и `favorites` (до 200).
- `updatedAt`: серверная временная метка.

## Проверенные сценарии атак

| Сценарий | Результат |
| --- | --- |
| Чтение без входа | Запрещено: требуется `request.auth`. |
| Чтение или запись чужого пути | Запрещено: UID в пути должен совпасть с `request.auth.uid`. |
| Подмена `ownerId` при создании | Запрещено: поле равно UID пути. |
| Подмена `ownerId` при обновлении | Запрещено: поле неизменно и валидируется снова. |
| Добавление неожиданных полей | Запрещено: допускаются только три поля верхнего уровня. |
| Удаление обязательного поля | Запрещено: обязательные поля проверяются для create и update. |
| Большой список поездок или избранного | Запрещено ограничениями в 100 и 200 элементов. |
| Публичный доступ к другим коллекциям | Запрещён правилом default deny. |

Это прототип правил, рассчитанный на текущую структуру одного снимка
планировщика. Перед широким запуском его нужно проверить на эмуляторе Firestore
и повторно пересмотреть при изменении модели данных.

## Развёртывание правил

Firebase CLI-конфигурация, правила и индексы хранятся в `config/firebase/`, чтобы не перегружать корень репозитория. Для развёртывания используйте:

```bash
firebase --config config/firebase/firebase.json deploy --only firestore
```
