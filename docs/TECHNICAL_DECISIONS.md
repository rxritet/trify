# Технические решения

| Решение | Причина и граница |
| --- | --- |
| Одна Flutter-кодовая база | Android и web используют одинаковые сценарии без дублирования интерфейса. |
| `core/` + `features/` | Общие механизмы отделены от пользовательских функций `auth` и `planner`. |
| Условное локальное хранилище профиля | Android использует SQLite, а web — хранилище браузера. |
| Локальная копия + Firestore для Google-пользователя | Планировщик остаётся доступным после перезапуска, а авторизованный пользователь получает синхронизацию. |
| Repository для мест | Виджеты не знают об HTTP; источник можно заменить без переписывания экранов. |
| Два независимых CI-процесса | Android APK и web-артефакт собираются отдельно и не попадают в Git. |

Эти решения описывают текущий код. Карты, уведомления, GoRouter, Riverpod и публичный Play-релиз остаются будущими задачами, а не частью этой архитектуры.
